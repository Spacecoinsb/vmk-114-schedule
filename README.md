# Расписание ВМК, группа 114

Бесплатное приложение на GitHub Pages. React + Vite, локальное хранение расписания и service worker для доступа без сети.

## Как обновляются пары

1. GitHub Actions (`pages.yml`) запускается при публикации, вручную и по расписанию `7,22,37,52 * * * *` (UTC). Запуск по расписанию может задерживаться.
2. `scripts/source-check.mjs` читает раздел бакалавриата ВМК, находит актуальную ссылку первого курса и скачивает PDF независимо от изменения даты или имени файла.
3. `public/parser.mjs` выбирает группу 114 по границам ячеек PDF, включая объединённые лекции, преподавателей, аудитории и ограничения по датам. PDF.js 4.10.38 находится в `public/vendor` и выполняется на Node 24 в GitHub Actions.
4. Проверенные пары, SHA-256 PDF и время успешной проверки публикуются одним `source.json`. При ошибке публикуются время неудачной попытки и причина; предыдущие пары/PDF и время успешной проверки сохраняются.
5. Приложение получает этот снимок при открытии, возвращении во вкладку, восстановлении сети и каждые 10 минут, пока вкладка видима. Кнопка «Обновить» получает последний опубликованный снимок и не запускает GitHub Actions.
6. Валидный снимок заменяет пары и сохраняется в localStorage. Изменения сравниваются с предыдущей версией. Соответствующий PDF скачивается отдельно, проверяется по SHA-256 и сохраняется в Cache Storage. Ошибка сохранения PDF не отменяет сохранённые пары.

Статус различает проверку ВМК, попытку проверки и получение данных устройством. Через 45 минут без успешной проверки появляется предупреждение. Это также позволяет заметить остановку workflow или неудачную публикацию. Проверка не гарантирует сведений новее опубликованного PDF; сообщения на стендах и другие разделы ВМК не обрабатываются.

## Проверка изменений

```sh
npm ci
npm run check
npm test
npm run build
```

На GitHub Pages сборка выполняется с `VITE_BASE=/vmk-114-schedule/`. `scripts/after-build.mjs` подготавливает пути PWA и версию офлайн-кэша. Для локального запуска: `npm run dev`.

`tests/schedule.test.mjs` использует зафиксированный PDF, чтобы будущие изменения ВМК не ломали регрессионные проверки. Проверяются извлечение 22 занятий, подгруппы, аудитории, ограничения по датам, замена старого расписания, ошибки сети/формата и достоверность статуса.

`tests/browser.mjs` проверяет готовую сборку в Chromium: мобильную вёрстку, реальный офлайн-режим с перезагрузкой, PDF при первом посещении, применение изменённой аудитории, историю и сохранность данных при ошибках. Требуется Playwright (можно указать путь к его `index.mjs` через `PLAYWRIGHT_MODULE`); `BROWSER_CHANNEL` по умолчанию `msedge`.

## Ограничения

Парсер рассчитан на нынешнюю таблицу ВМК. При изменении структуры он сохраняет последнюю проверенную версию и публикует ошибку. Очистка данных браузера удаляет офлайн-копию; для её восстановления потребуется интернет. Приложение на закрытом iPhone не выполняет фоновые запросы: сервер проверяет ВМК, телефон получает результат при следующем открытии.
